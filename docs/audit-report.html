2 · Program — NEW findings (all executable-PoC verified unless noted)

CRITICALC-1 · P2P principal mint is unbound — zero-cost collateral theft POC VERIFIED (poc1)
state.rs:163-183 (P2POffer has no liquidity-mint field) · processor.rs:1804-1825, 2131-2135

FundP2POffer checks only that the creator's destination account is owned by the creator. The attacker (1) creates a mint they control, (2) permissionlessly creates the creator's ATA for it via the ATA program, (3) "funds" the offer with worthless units. The offer is Funded; the creator's later USDC repayment fails MintMismatch; the attacker triggers grace and claims the real SKR/SOL collateral. Executed end-to-end in solana-program-test: creator left with zero value, collateral with the attacker, no reject/cancel path after funding.

Fix: add liquidity_mint to P2POffer (set at creation) and enforce source.mint == dest.mint == offer.liquidity_mint in fund and in the repay offer-branch (the defined-but-unused USDC_DEVNET_MINT constant is the intended allowlist).
HIGHH-1 · P2P repay becomes impossible once grace starts — funder seizes solvent creators POC VERIFIED (poc2 / probe C)
processor.rs:2106-2108

Offer repay requires status == Funded exactly; pool loans accept Active | InGracePeriod (1892). At due time the funder triggers grace → the solvent creator can never repay → collateral forfeited 24 h later. A "grace period" that removes the borrower's only remedy.

Fix: accept Funded | InGracePeriod in the offer repay branch.
HIGHH-2 · ClaimDefault silently no-ops without the token program — collateral stranded forever POC VERIFIED (poc3 / probe E)
processor.rs:2485, 2486

For SPL-collateral pool loans, if the caller omits the token program (or the treasury), the whole transfer block is skipped while the loan is still stamped Defaulted. Escrow keeps the collateral; no instruction can ever move it again (2nd claim → GracePeriodActive; repay → LoanAlreadyRepaid).

Fix: token_program_opt.ok_or(InvalidInstruction)? for SPL collateral, require the treasury up front, and write the terminal status only after transfers succeed.
HIGHH-3 · CreateP2POffer allows dropping the oracle entirely — funders misled ~10× on LTV POC VERIFIED (probe F / poc6)
processor.rs:1630-1655

When the oracle account is absent or not the canonical PDA, the branch falls through to hardcoded baselines ($150 SOL / $0.02 SKR) — no is_oracle_free gate, unlike the pool path. With the admin's real feed at $0.002/SKR, a 1,000-SKR-for-18-USDC offer is rejected at 900% LTV with the oracle but accepted without it. The 90% ceiling constrains nothing against the real market.

Fix: fail closed when the canonical feed is missing/unprovisioned; never substitute a hardcoded constant on a path that authorizes value.
HIGHH-4 · Locked SKR bond orphaned on the default path — StakeLocked forever POC VERIFIED (poc4 / probe E)
processor.rs:2429-2430, 2566, 2606-2608

The loan zeroes its own locked_skr, but the profile's locked_skr is released only when the SKR escrow and token program are both present — no else. Post-claim: profile.locked_skr = 1e9 with no path to release → UnstakeSKR fails StakeLocked permanently. Re-opens the bond-evasion class via caller-supplied account lists.

Fix: require the profile (and escrow when a bond exists) on the claim path, exactly as repay does (2070-2074).
HIGHH-5 · 1 base unit of donated dust permanently bricks CancelP2POffer POC VERIFIED (poc5 / probe D)
processor.rs:2867-2881

Escrow token PDAs are publicly creditable; close_account requires a zero balance. Anyone transfers 1 base unit into the escrow → cancel fails NonNativeHasBalance → the creator's only unilateral exit is destroyed for a dust-cost grief.

Fix: transfer the full escrow balance before closing (like the native-SOL branch), or close only when the balance equals the recorded collateral.
