2 · Program — remaining/new findings (all probe-verified)

HIGHF1 · SKR-collateral loans can never be liquidated — the default collateral class is unenforceable POC VERIFIED ×2 INDEPENDENT AUDITORS
processor.rs:2427-2438, 2492-2508, 2551-2586

In ClaimDefault, any treasury-owned token account of the SKR mint is captured by the slash-destination classifier (2431-2434), so treasury_collateral_opt can only ever hold a treasury account of a different mint. The 5% margin transfer then dies: raw treasury PDA → InvalidAccountData; non-SKR treasury account → MintMismatch; treasury-owned SKR account → classifier claims it → InvalidTreasuryAccount. Executed traces: all three configurations revert; the loan stays InGracePeriod; the SKR stays frozen in escrow. Only collateral_amount < 20 (margin rounds to 0) ever succeeds. SOL collateral works (control probe).

Borrower takes an SKR-collateral loan (the app's default collateral), never repays → the pool authority cannot seize anything even after grace expires. De facto unsecured lending for the default collateral class; total_borrowed never unwinds.
Fix: classify the treasury by role, not mint — accept an explicit treasury account validated as owner == treasury PDA && mint == collateral_mint && key != destination, and exclude it from slash-destination selection (or keep the full-transfer branch when treasury == destination). Add a real SPL-collateral claim test — the gap that let this survive: every existing claim test uses collateral_mint: Pubkey::default().
  • F2 (MED) — legacy 170-byte offers are permanently bricked. The migration slice is [..168] for a 170-byte struct → fund/repay/claim/cancel all fail closed forever; pack_into_slice requires ≥ 202. No migration instruction exists. No live legacy offers today (zero on-chain), but the claimed migration does not work.
  • F3 (MED) — hardcoded UPGRADE_AUTHORITY root. processor.rs:27/777 accepts the key unconditionally, can create/rotate AdminConfig → controls global prices and all treasury withdrawals, even after a future authority rotation. Delete the constant or assert it equals the live upgrade authority at init.
  • F4 (MED) — dead 16..48 ProgramData branch (see §1 M-1 row; keep 13..45, delete the misleading branch and the 1u32 comment).
  • F5 (MED) — P2P liquidity_mint is un-allowlisted and unit-mismatched. Any token-owned 82-byte account is accepted as the liquidity mint (1668-1671); requested_amount is compared in raw base units against a micro-USD value (assumes 6 decimals). A creator can request $1.35M worth of a 2-decimal token against $150 of collateral; a non-USDC client would sign it. Allowlist the mint (USDC/WSOL) or normalize by the mint's decimals.
  • F6 (LOW) — collateral routed to pool.vault_pda is trapped (raw lamports into a WSOL token account; no sweep instruction). Restrict the destination to the authority wallet.
  • F7 (LOW) — is_oracle_free is a name-prefix flag (the third disjunct is dead code — borsh rejects trailing bytes). Make it an explicit instruction field.
  • F8 (LOW) — no late interest / permissionless grace: a passive lender accrues nothing past maturity and must trigger grace manually.
  • INV (LOW, informational) — legacy 51-byte profile realloc reinterprets rather than translates (reputation resets to 0); staked_skr_amount write-only drift; rent stranding on SPL escrows and terminal PDAs; admin can override pool-scoped feeds (centralized-trust caveat).
